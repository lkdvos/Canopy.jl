### Scheduling bounds on the unit loop

Speedup ceilings from the per-unit work vector at `nthreads` = 2 / 4 / 8 / 16.
`dyn` is `total / max(longest unit, total/t)`, which no schedule can beat.
`static` is contiguous chunking — the obvious first implementation. `lpt` is the
deterministic longest-processing-time-first assignment, which is what
`unit_call_threaded!` uses, and it is deterministic **on purpose**: work
stealing would balance just as well but would put a unit in a different
per-thread partial sum from run to run, which is incompatible with the bitwise
reproducibility §2's hazard table asks for.

Work is `copy + flop` weighted 1:1, which is a proxy — see `census_row`.

## Threaded unit loop

`serial` is the *same call* at `nthreads = 1`, so `speedup` isolates the
threading; `vs real` divides by the real kernel's time from the `--serial`
table and is the figure that matters. `repro` — two runs at this `nthreads`,
bitwise — is the determinism a fixed unit→thread map plus a fixed reduction
order actually buys. `vs_real` is the **race check**: disjoint bands are only
disjoint if the plan says so, and the probe refuses to report a speedup for a
row where it exceeds 1e-12.

`vs_ser` (threaded against `nthreads = 1`) is at rounding level *by
construction* and is **not** a defect: partitioning a sum across `t` buffers
regroups the additions, and floating-point addition is not associative. §2's
hazard table asks for `nthreads == 1` bitwise equal to `t`-thread, which no
implementation can give; `repro` is the achievable half of that request.

`lpt` is the deterministic longest-processing-time-first assignment; `dynamic`
is `nthreads` tasks pulling unit indices off one atomic counter, which needs
**no work model at all**. If the two match, the plan's work estimate can be
deleted. `dynamic` is not reproducible run to run by construction, which is
fine — it is recorded, not required.
