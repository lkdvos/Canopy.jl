### Scheduling bounds on the unit loop

Speedup ceilings from the per-unit work vector at `nthreads` = 2 / 4 / 8 / 16.
`dyn` is `total / max(longest unit, total/n)`, the bound no schedule can beat;
`static` is what the contiguous chunking in `unit_call_threaded!` actually
assigns, on the same fixed unit order. **Where the two agree there is no
reason to implement dynamic scheduling.** Work is `copy + flop` weighted 1:1,
which is a proxy — see the note in `census_row`.

bitwise identical to the real one; `unit` is the same kernel with the outer
